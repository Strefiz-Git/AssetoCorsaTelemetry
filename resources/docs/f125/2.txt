F1 25 outputs live race and car data via a UDP (User Datagram Protocol) stream that external apps can capture, parse, and display.Official documentation and packet layouts are released directly by EA Sports and Codemasters on the EA Forums Game Info Hub, where you can download the official PDF guide (Data Output from F1 25 v3.pdf) and text layout structures.1. Enabling Telemetry in F1 25To make your app receive data, configure the in-game settings:Open Options > Settings > Telemetry Settings.Set UDP Telemetry to On.Set UDP Broadcast Mode to Off (unless multicasting across a network).Set UDP IP Address to 127.0.0.1 if running your app on the same PC, or your device's local IPv4 address (e.g., 192.168.x.x) for mobile/remote apps.Set UDP Port to 20777 (the default standard port).Set UDP Send Rate to 30 Hz or 60 Hz (60 Hz is recommended for smooth live dashboards).Set UDP Format to 2025 (or switch to 2024/2023 compatibility modes if using older parser libraries).2. Core Packet ArchitectureEvery packet sent by the game starts with a 29-byte common Packet Header, followed by a specific payload depending on the packet ID:Packet IDNameDescription0MotionWorld/local position, velocity, g-force, rotation, suspension positions.1SessionTrack ID, weather, session type, time remaining, safety car status.2Lap DataLap times, sector times, distance around track, car status flags.3EventFast lap, retirement, penalty, lights out, chequered flag notifications.4ParticipantsDriver names, nationalities, team IDs, controller types.5Car SetupsAerodynamics, transmission, suspension, and tyre pressures.6Car TelemetrySpeed, throttle, steer, brake, clutch, gear, engine RPM, DRS, tyre temps/pressures.7Car StatusTraction control, ABS, fuel mix, fuel remaining, max RPM, tyre damage/wear.8Final ClassificationPost-race standings, points, penalties, and lap counts.9Lobby InfoMultiplayer lobby player specs and readiness.10Car DamageWear, punctures, wing damage, floor/diffuser and engine damage.11Session HistoryLap time details and tyre history for all completed laps.3. Building a Parser (Quick Start)If you are building your app in Python, you can catch and unpack the binary stream using Python's built-in socket and struct modules:Listen to the socket: Bind a UDP socket to ('0.0.0.0', 20777) and call .recvfrom(2048) inside an active loop.Parse the Header: Unpack the first 29 bytes to read fields like m_packetFormat (should equal 2025), m_packetVersion, m_packetId, and m_playerCarIndex.Unpack Payloads: Use struct.unpack_from() with little-endian format specifiers (< prefix) matching the official field offsets.Reference Open-Source LibrariesTo avoid writing byte-parsers from scratch, you can study existing open-source implementations:Python / General: Check out reference codebases like Fredrik2002/f1-25-telemetry-application or beamuu/f1-telemetry.C# / .NET: Use the official NuGet package F1Game.UDP.Rust: Use f1-game-library-models-25.
